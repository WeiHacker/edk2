# Pcle-作业报告

## 1. 作业题目

### 1.1 开发一个 lspci 风格的 UEFI Shell 应用程序（100 分）

实现一个名为 `LspciApp` 的 Shell 应用程序，通过 I/O 端口（0xCF8/0xCFC）直接访问 PCI 配置空间，支持以下功能：

- **基本模式**（20 分）：枚举所有 PCI/PCIe 设备，输出 BDF、Vendor ID、Device ID 和设备类别名称。
- **`-v` 详细模式**（30 分）：显示 Revision、Header Type、Subsystem VID/DID、BAR 解码（类型/地址/大小属性）、中断引脚和线路号、能力列表。
- **`-x` HEX Dump 模式**（15 分）：输出每个设备的 256 字节配置空间原始 HEX dump。
- **`-tv` 树形拓扑模式**（35 分）：以树形结构展示 PCI 总线拓扑，PCI-PCI Bridge 下游设备正确缩进。

要求不使用 UEFI Protocol 服务，完全通过 I/O 端口访问实现。

## 2. 思路

### 2.1 lspci 工具设计框架

[插入图片：LspciApp 整体架构图]

LspciApp 遵循标准的 UEFI Application 模式（`ShellCEntryLib` 入口），采用 **两遍扫描** 策略：

```
第一遍扫描（计数）
    |
    ▼
为所有设备分配 PCI_DEVICE_INFO 数组
    |
    ▼
第二遍扫描（采集信息）
    |  ├─ 基本参数：VID, DID, Revision, Class Code
    |  ├─ Header Type → Type 0/1/2 判定
    |  ├─ BAR[0-5] 原始值读取
    |  ├─ Subsystem VID/DID
    |  ├─ 中断信息：IntPin, IntLine
    |  ├─ Capabilities Pointer 链表遍历
    |  └─ PCIe Capability 检测 (Cap ID = 0x10)
    |
    ▼
根据命令行参数选择输出模式：
    ├─ 基本模式 → "B:D.F VID:DID ClassName"
    ├─ -v 模式  → PciPrintVerbose (Level=1)
    ├─ -vv 模式 → PciPrintVerbose (Level=2，含能力详细解码)
    ├─ -x 模式  → PciDumpHex 逐设备输出 256 字节
    └─ -tv 模式 → PciBuildTree + PciPrintTree 递归输出
```

**文件架构：**

```
StudyPkg/LspciApp/
├── LspciApp.inf       # UEFI_APPLICATION，ShellCEntryLib 入口
├── LspciApp.h         # PCI_DEVICE_INFO 结构体、函数声明、寄存器常量
└── LspciApp.c         # 完整实现：~996 行
```

### 2.2 PCI 设备信息结构体

[插入图片：PCI_DEVICE_INFO 结构体字段图]

核心数据结构 `PCI_DEVICE_INFO` 存储单个 PCI 设备的完整信息：

| 字段 | 大小 | 来源 |
|------|------|------|
| Bus/Device/Function | 各 1 字节 | 扫描时的 BDF 参数 |
| VendorId/DeviceId | 各 2 字节 | 偏移 0x00-0x04 |
| RevisionId | 1 字节 | 偏移 0x08 |
| ClassCode | 3 字节 | 偏移 0x09-0x0B |
| HeaderType | 1 字节 | 偏移 0x0E（Bit 7 = Multi-Function） |
| IntPin/IntLine | 各 1 字节 | 偏移 0x3C-0x3D |
| Bar[6] | 6×4 字节 | 偏移 0x10-0x24 |
| SubVendorId/SubDeviceId | 各 2 字节 | 偏移 0x2C-0x2E |
| Capabilities[16] | 16 字节 | Capability 链表遍历结果 |
| CapCount | 1 字节 | 能力数量 |
| IsPcie | 1 字节（BOOL） | 是否检测到 Cap ID = 0x10 |
| PcieDeviceType | 1 字节 | PCIe Cap 寄存器中的 Device/Port Type |
| Primary/Secondary/SubordinateBus | 各 1 字节 | Type 1 Bridge 专用，偏移 0x18-0x1A |

### 2.3 PCI 类别名称查找表

[插入图片：PCI Class Code 层次结构图]

PCI Class Code 分为三级（Base Class / Sub Class / Programming Interface），LspciApp 实现了约 70 条名称映射条目（`mClassNameTable`），涵盖从 0x00（Legacy）到 0x40（Co-Processor）的所有主要类别：

```c
typedef struct {
  UINT8   BaseClass;    // 基类
  UINT8   SubClass;     // 子类
  CHAR16  *Name;        // 人类可读名称
} PCI_CLASS_ENTRY;
```

查找逻辑：先精确匹配 Base + Sub Class；若未命中，回退到 `SubClass = 0x80`（"...controller" 泛化名称）；仍失败则返回 `"Unknown device"`。

### 2.4 Capability 链表遍历

PCI Capability 链表起始于偏移 `0x34`（Capabilities Pointer），每个能力条目格式：

```
Offset + 0: Capability ID (1 字节)
Offset + 1: Next Pointer (1 字节) → 指向下一个 Capability
Offset + 2..N: Capability 特定数据
```

[插入图片：PCI Capability 链表遍历流程图]

LspciApp 遍历实现关键逻辑：

```c
CapPtr = PciReadByte (Bus, Device, Function, PCI_CAP_PTR);

while ((CapPtr != 0) && (Idx < 16)) {
    if (CapPtr >= 0x40) {
        Capabilities[Idx] = PciReadByte (Bus, Device, Function, CapPtr);
        if (Capabilities[Idx] == CAP_PCIE) {
            IsPcie = TRUE;
            // 读取 PCIe Device Type
        }
        Idx++;
        CapPtr = PciReadByte (Bus, Device, Function, CapPtr + 1);
    } else {
        break;  // 异常指针，停止遍历
    }
}
```

支持识别 19 种标准 Capability ID（PM、AGP、MSI、PCI-X、HT、PCIE、MSI-X 等）。

### 2.5 BAR 解码

[插入图片：PCI BAR 寄存器格式图]

LspciApp 的 `PciDecodeBar` 函数对每个 BAR 进行完整解码：

| Bit | 含义 |
|-----|------|
| Bit 0 | 0 = Memory BAR, 1 = I/O BAR |
| Bit 1-2 (Memory) | 00 = 32-bit, 01 = 保留, 10 = 64-bit |
| Bit 3 (Memory) | 0 = Non-prefetchable, 1 = Prefetchable |
| Bit 1-31 (I/O) | I/O 端口基址（低 2 位为 0） |
| Bit 4-31 (Memory) | 内存基址（低 4 位为 0） |

输出示例：
```
Region 0: Memory at 0x80000000 (32-bit, prefetchable, 32-bit)
Region 4: I/O ports at 0xC000
```

### 2.6 树形拓扑构建算法

[插入图片：PCI 树形拓扑构建流程图]

树形拓扑使用 `PCI_TREE_NODE` 结构体：

```c
typedef struct _PCI_TREE_NODE {
    PCI_DEVICE_INFO        *Device;
    struct _PCI_TREE_NODE  *Child;    // 下游总线设备列表
    struct _PCI_TREE_NODE  *Sibling;  // 同总线下一个设备
} PCI_TREE_NODE;
```

`PciBuildTree` 递归算法：

```
PciBuildTree (&Root, Bus=0, Devices, Count):
    for each device on Bus:
        create node, append to sibling list
        if device is PCI-PCI Bridge (Header Type 1) AND SecondaryBus ≠ 0:
            PciBuildTree (&Child, SecondaryBus, Devices, Count)
            node->Child = ChildRoot
```

`PciPrintTree` 递归遍历：

```
PciPrintTree (Root, Depth):
    for each node in sibling list:
        print Depth*2 spaces
        if has sibling: print "+-" else print "\-"
        print "B:D.F VID:DID ClassName"
        if has child: PciPrintTree (child, Depth+1)
```

## 4. 遇到问题

### 4) 两遍扫描的内存开销

**现象：**

LspciApp 对 PCI 总线进行了两遍完整扫描：第一遍计数设备数量，第二遍再次扫描采集详细信息。在只有 5 个设备的 QEMU 模拟环境下并无问题，但在有数百个 PCI 设备的真实机器上效率较低。

**原因分析：**

两遍扫描的设计是为了先确定 `MaxDevices`，再预分配 `PCI_DEVICE_INFO` 数组。这是 C 语言中动态数组分配的常见模式，但 PCI 扫描的 I/O 操作（0xCF8/0xCFC）本身有延迟，两遍扫描将延迟加倍。

**方案讨论：**

有几种替代方案：
1. **链表动态追加**：使用 `AllocatePool` 逐设备申请节点，用链表链接，最后转换为数组。避免第一遍计数，但指针开销和碎片化在 UEFI 环境下可能不可控。
2. **预估上限**：直接分配 `256 × 32 × 8 = 65536` 个条目的最大容量（实际设备远少于该值），用 UEFI 的 `AllocatePool` 一次性申请 `65536 × sizeof(PCI_DEVICE_INFO)` ≈ 8MB。对 UEFI 环境来说可以接受，但不够优雅。
3. **单遍扫描 + 直接输出**：边扫描边输出，不保存设备列表。最简单，但无法支持 `-tv`（需要先建立完整设备列表才能构建树）。

**启示：** 当前的两遍扫描在正确性和可维护性之间取得了平衡。对于实际产品，应采用方案 3（非树模式）和方案 1（树模式）的混合策略。

### 5) `-tv` 树形打印缺少竖线连接符

**现象：**

当前的 `PciPrintTree` 实现仅使用缩进空格来区分层级，没有使用 `│`（竖线）连接线来清晰标示父-子关系。当树形结构较深时，难以直观追踪每个子设备的父设备。

**原因分析：**

实现一个正确的树形打印算法需要跟踪每一层级的"最后一个子节点"状态，以决定当前行打印 `│  ` 还是 `   `（空白）。这需要维护一个 `depth 状态数组`，记录每个层级是否还有后续兄弟节点。

**示例（理想输出 v.s. 当前输出）：**

```
理想输出：                    当前输出：
-[0000:00]-                  -[0000:00]-
├─00:00.00 Host bridge       +-00:00.00 Host bridge
├─00:01.00 ISA bridge        +-00:01.00 ISA bridge
│  ├─00:01.01 IDE ctrl       +-00:01.01 IDE controller
│  └─00:01.03 Bridge         +-00:01.03 Bridge
└─00:02.00 VGA ctrl          \-00:02.00 VGA compatible controller
```

**方案讨论：**

增补 `PciPrintTree` 的扩展版本 `PciPrintTreeEx`，接收一个 `BOOLEAN LastChild[]` 数组记录每一层级的后续兄弟状态：

```c
VOID
PciPrintTreeEx (
  IN PCI_TREE_NODE  *Root,
  IN UINTN          Depth,
  IN BOOLEAN        *LastFlags,
  IN BOOLEAN        IsLast
  )
{
  UINTN  Index;
  BOOLEAN NewFlags[16];

  CopyMem (NewFlags, LastFlags, Depth * sizeof (BOOLEAN));
  NewFlags[Depth] = IsLast;

  for (Node = Root; Node != NULL; Node = Node->Sibling) {
    for (Index = 0; Index < Depth; Index++) {
      ShellPrintEx (-1, -1, LastFlags[Index] ? L"   " : L"│  ");
    }
    ShellPrintEx (-1, -1, Node->Sibling ? L"├─" : L"└─");
    // ... print device info ...
    if (Node->Child != NULL) {
      PciPrintTreeEx (Node->Child, Depth + 1, NewFlags, Node->Sibling == NULL);
    }
  }
}
```

**启示：** 树形打印看似简单，但涉及递归和层级状态的正确维护。Unicode 制表符（`├─ └─ │`）能显著提升可读性，是值得投入的增强方向。
